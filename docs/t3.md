# T3 integration findings

- `app.t3.codes/settings/connections` pairs a browser to a T3 backend.
- It does not configure an OpenCode server.
- Provider settings appear only after a T3 backend connects.
- OpenCode provider settings accept an external server URL.
- T3 does not own an external OpenCode server.
- Hosted T3 requires its backend over HTTPS/WSS.
- Hosted T3 cannot pair directly to plain localhost HTTP/WS.
- Local T3 dev prints a one-time pairing URL.
- macOS local dev can bind `localhost` only to IPv6; launch IPv4-first for IPv4 clients.
- Use `127.0.0.1` in the pairing URL when localhost DNS family differs.
- Shim session cwd is restricted to canonical paths under `PI_ALLOWED_ROOTS`.
- Unset `PI_ALLOWED_ROOTS` defaults the boundary to `PI_CWD` (or launch cwd).
- Symlinked cwd paths escaping an allowed root are rejected.
- Persisted sessions outside the roots are hidden and cannot be reopened.
- Cwd and root paths must resolve to existing filesystem paths.
- Local T3 dev requires Node 24 and Vite+ (`vp`).
- T3 checks `GET /global/health` before loading OpenCode models.
- T3 requires the reported OpenCode version to be at least `1.14.19`.
- Shim reports OpenCode compatibility version `1.14.19`.
- Pi already completes synchronous prompts through the shim.
- Pi already completes async prompts through the shim SSE stream.
- Bun closes a quiet SSE stream after 10 seconds unless its idle timeout is disabled.
- Shim disables Bun idle timeout for durable SSE.
- T3 must see the Pi model it can actually select, not a synthetic model label.
- T3 begins each OpenCode session by recovering pending permissions and questions.
- Empty `GET /permission` and `GET /question` responses mean no pending requests.
- T3 assigns each submitted user message an ID.
- The shim must preserve that ID in snapshots and events.
- Caller message IDs persist in Pi session custom entries and survive reopen.
- Streamed message metadata uses configured provider/model IDs.
- Every shim status event includes native `status` plus legacy `sessionStatus`.
- Status event properties include `sessionID` for T3 filtering.
- Pi returned `T3_PI_OK` through T3’s submitted prompt.
- T3 ignores provider events without `properties.sessionID`.
- Native stream events use `message.updated`, `message.part.updated`, and `session.status`.
- T3’s new-thread default is not necessarily OpenCode; select `configured` explicitly.
- Playwright live coverage pairs a disposable T3 backend and selects `configured` before chat.
- T3 has no `T3CODE_*` environment variable for an external OpenCode URL.
- Local dev reads `$T3CODE_HOME/dev/settings.json`; persist `providers.opencode.serverUrl` and `enabled: true` there.
- Persist `providers.codex.enabled: false` and `providers.claudeAgent.enabled: false` to make OpenCode the only enabled default provider.
