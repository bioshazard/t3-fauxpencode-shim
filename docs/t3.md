# T3 integration findings

- `app.t3.codes/settings/connections` pairs a browser to a T3 backend.
- It does not configure an OpenCode server.
- Provider settings appear only after a T3 backend connects.
- OpenCode provider settings accept an external server URL.
- T3 does not own an external OpenCode server.
- Hosted T3 requires its backend over HTTPS/WSS.
- Hosted T3 cannot pair directly to plain localhost HTTP/WS.
- Local T3 dev prints a one-time pairing URL.
- Local T3 dev requires Node 24 and Vite+ (`vp`).
- T3 checks `GET /global/health` before loading OpenCode models.
- T3 requires the reported OpenCode version to be at least `1.14.19`.
- Shim reports OpenCode compatibility version `1.14.19`.
- Bun’s default 10s idle timeout kills T3’s long-lived SSE.
- Shim disables Bun idle timeout for `/event` durability.
- Pi already completes synchronous prompts through the shim.
- Pi already completes async prompts through the shim SSE stream.
- Bun closes a quiet SSE stream after 10 seconds unless its idle timeout is disabled.
- T3 must see the Pi model it can actually select, not a synthetic model label.
